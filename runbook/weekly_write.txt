## 役割
米国株指標チェックの週次レポート（マスター仕様 v4.2 の D7「週次」）を書く。
直近の金曜（米国の通常取引の終値）を基準に、マクロ全分野・Broad・Tape・行動・半導体テクノロジーをまとめる。モードは Standard か Full。

## 進め方（この順に。00 の F3 の3段階）
1. このファイルを最後まで読む。
2. 仕様を読む（下の「仕様」）。
3. データ確認（F3 の Step1）：入力を読む（下の「入力」）。
4. モードを決める（下の「モードの決め方」）。
5. 調べる：マクロなど Web で取る値を集める（下の「原則」「Web取得の注意」）。
   調べた値は、出典・基準日・単位・データ状態と一緒に /home/claude/out/research.md に控える（項目を書くときに、ここから引く。会話の記憶に頼らない）。
6. 判定（F3 の Step2）：Broad、Tape（C15.1 のチェックリストと C15.2）、Alignment、ゲート、L/H、候補状態、売り検討シグナルを決め、/home/claude/out/research.md に控える。
7. 書く（F3 の Step3）：「ひな形」の表の項目を書く。
   書き始める前に、「ひな形」の表の行（32行）をやることリストに入れる（TaskCreate が使えるとき。無ければ /home/claude/todo.md に書く）。1つの節を書き終えるごとに消す。
   2項から25項まで順に、1つの節ごとに次の3つを繰り返す：
   (a) その節のファイル（ひな形の表の「書く直前に読むもの」。節のファイルは runbook/weekly/ にあり、00〜08 は条項の部分だけ読む）を読む。
   (b) その節を書く。
   (c) その節のファイルを上から1行ずつ見て、書いた内容と突き合わせる（1行が1つの決まり。その日は当てはまらない行は飛ばす）。足りないものがあれば、その場で足す。
   節のファイルを先にまとめて読まない（書く直前に読むほうが、その節の決まりを落とさないため）。
   題と作成の行・冒頭ブロック（今日のひとこと・なぜその判断か）は、ほかの節を書き終えてから最後に書き、レポートの先頭に置く（全部の節の中身がそろってからまとめるため）。
   途中で止まらない：全部の節と「書き終えたら」が済むまで、文だけの返答で終えない（返答を終えると、そこで作業が止まる）。
   まとめの項目（1項・3項・4項・26項・27項）は、2項と5〜25項を書き終えてから書く（中身がそろってからまとめるため）。そのあとで題・冒頭ブロック・「読み方」を書く。置く場所は、ひな形の順のまま。
   節のファイルが無い項目は、表にある仕様の条項を読み、(c) ではその条項と突き合わせる。
8. 書き終えたら、下の「書き終えたら」を行う。

## 原則
- 計算はGitHubの解析エンジン（analyze.py）が済ませている。
  Tapeチェックリスト、先導候補、セットアップ、ブレイク追跡、売りシグナル、
  セクター相対強度・調整耐性・RSライン、市場内部の拡張（breadth_ext）、先導セクターの推移（leadership）、ヘッジ条件（hedge）、
  長期SPY配分モデル（spy_model）、週足ステージ・業種別のステージ分布・ベースの番号（stages、setups の stage_label・base_count）、ポケットピボット（pocket_pivots）、
  利益確定の目安・8週ルール（profit_tracking）は signals.json・ledger.json の値を使い、再計算しない
  （検証目的は可。食い違いは signals.json を優先して報告）。
  それ以外の時系列計算（SMA、HV等。stages.etfs に無いETFの週足ステージ）はPythonで行い、その場合も07のE6.2の決め方に合わせる。
- マクロ、金融政策、金利、景気・雇用・物価、企業利益・EPS修正、評価、信用・ボラ、心理・フロー・FINRA、ドル・商品・地政学、
  セクター、季節性、次週のイベントはWeb検索で取得し、出典・基準日・単位・データ状態を付ける。
- 推測で埋めない。
  未確認の値は missing とし、D4のデータゲートを適用する。
- ユーザーの口座・保有は未提供として扱い、数量は出さない（チャットで示された範囲だけ使う）。
- 個別分析は半導体・テクノロジーの監視銘柄だけ。
  市場全体の先導候補はTape判定とセクター分布の表示にだけ使う。
- GitHubのリポジトリのファイルは変更しない。
  例外は、データが古いときのワークフロー起動（weekly_runbook.txt 第2節）、レポート本文の reports/ への保存（同 第7節）、reports/flows/fuel_latest.yaml の更新（14項）だけ。

## Web取得の注意
- WebFetch は「検索結果に出たURL」か「会話中にすでに出たURL」しか取得できない（手順書に書いたURLをそのまま渡すと PROVENANCE_REQUIRED で拒否される）。
  先に WebSearch で該当ページを出してから取得する。
  取得できない値は missing（または period_mismatch で前回値）とし、代わりの取得先があれば使う：
  ・米10年実質金利（DFII10）・米10年名目（DGS10）・広義ドル指数（DTWEXBGS）、米2年金利（DGS2）・HY OAS（BAMLH0A0HYM2）・CCC格のスプレッド（BAMLH0A3HYC。この3つは 2026-11-10 以降のデータにある）：半導体側リポジトリ semis-data の data ブランチ macro_daily.csv（FREDから機械取得、1〜2日遅れ）。
   Web で探す前に、まずここを読む。
    `git clone -q --depth 1 --branch data https://github.com/bakaho19920625-wq/semis-data.git /home/claude/sd-data` → macro_daily.csv。
    出典は FRED、状態は verified（基準日を添える）。
  ・FactSet Earnings Insight：WebSearch「FactSet Earnings Insight <日付>」で当週のPDFかInsightページを出してから取得。
   出なければ前週版を period_mismatch で使う。
  ・財務省のパー利回り：WebSearch「treasury par yield curve rates <年月>」で出た財務省ページを取得。
   出なければ市場まとめの値を reported_unverified で使う。
  CNBC・CNN・Bloomberg・WSJ・Reuters の本文は取得できないことが多い（見出しだけ使い reported_unverified）。

## 数字の出所と基準
- 個別銘柄・ETF・指数の騰落率と出来高は signals.json（market・tech_etf・sector_etf・movers）と screen.csv（chg_1d_pct・chg_1w_pct・rvol50）、週の騰落率は prices_daily.csv.gz から計算した値だけを書く（記事の騰落率は書かない。記事は理由の説明に使う）。

## モードの決め方
- 前回の週次が無ければ初回として Full にし、「前回比較不能」と明記する。
- Standard を基本とし、D7の Full 条件（その月の最初の週次、前回の Full から4週以上、Broad判定帯やTapeレジームの変更、重大イベント後、
  定義変更、前回の週次なし）に当たれば Full。
- 追補04の適用後で最初の週次は「定義変更」として Full にし、前回のレジームとの比較には「定義変更（v4.4）」と明記する
  （判定条件が変わったため、前回のEと今回のCは同じ定義での変化ではない）。
- どちらにしたかと理由を、レポートの冒頭に書く。
- ユーザーが「Fullで」と頼んだときは Full。
- Standard でも、ひな形の見出しは全部残す。重要な変化がない項目は、再確認日と据置の理由、または未取得を1〜3行で書く（00 の A3「無言で省略しない」）。
