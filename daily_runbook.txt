# 日次レポート 実行手順書（daily_runbook v1.5、マスター仕様v4.2のD7「Daily」の実装。v4.4・v4.5追補とやさしい表記を反映）
# 日次の自動実行（火〜土 12:07 JST、データ未更新なら 18:07 に再試行）はこの手順書に従う。
# 定期実行の本文には手順を書かず、この手順書を読む指示だけを置く。手順を変えるときはこのファイルを直す。
# マスター仕様は定義の確認が必要なときだけ該当条項を読む（C7.1、C15.1、C15.2、D4、D7、E9〜E14、F2.1、F4、F9、
# 追補03のE7.1〜E7.3、追補04のC15.1a〜d、追補06のE7.4・C10.1・F10。C15.1と04が食い違えば04を優先）。

## 0. 原則
- 計算はGitHubの解析エンジン（analyze.py）が済ませている。signals.json の値を再計算しない。
  検証のための再計算は可。食い違いがあれば signals.json を優先し、食い違いを報告する。
- 推測で埋めない。null や missing はそのまま「未確認」と書く。
- 口座・保有・売買ログはユーザーがチャットで示した範囲だけ使う。未提供なら数量を出さない。
- 本文は2〜3画面。冒頭ブロック（第1.5節）→ 重要ポイント（第2節）の順に先頭に置く。
- ［v1.4］書き方：状態を表す語は 05_Plain_Language_Glossary.txt（https://raw.githubusercontent.com/bakaho19920625-wq/market-data/main/05_Plain_Language_Glossary.txt。
  届かなければ保管ページの spec/plain_language.txt）の「言葉」で書き、数字と記号を括弧で後ろに付ける（例：大口が売った日が7日（IX2＝7、6日以上は危険水準））。
  記号は消さない。記号だけ・英語だけの行を作らない。表には「言葉」の列を置くか、数字の横に言葉を添える。巻末に「読み方」（使った記号だけ、1行ずつ）。
- GitHubのリポジトリ・ワークフローは操作しない（日次の実行環境には書き込み権限がない。データが古いときの扱いは第1節）。

## 1. 取得と確認
1. GitHub main ブランチの 02_User_Settings.txt を読む（https://raw.githubusercontent.com/bakaho19920625-wq/market-data/main/02_User_Settings.txt。届かなければ保管ページの spec/user_settings.txt）。他の仕様ファイルは必要時のみ。
2. GitHub data ブランチから manifest.json、signals.json、setups.csv を取得する。
   https://raw.githubusercontent.com/bakaho19920625-wq/market-data/data/<ファイル名>
   届かなければ git clone --depth 1 -b data https://github.com/bakaho19920625-wq/market-data.git
3. データの新しさ：
   - 直近の米国取引日（土日・NYSE休場日を除く、日本時間の今日の前日にあたるET日付）を求める。
   - 前日が休場日 → 「新しい取引日はありません（休場）」と短く送って終了（保存しない）。
   - signals.as_of_market_date がその取引日より古い（GitHubの予約実行は数時間遅れることがある）：
     ・日本時間15時より前の実行（12:07の1回目）→ ユーザーには何も送らず終了（保存しない）。18:07の再試行に任せる。
     ・日本時間15時以降の実行（18:07の再試行）→ 「GitHubのデータが更新されていません（基準日○○、生成○○）」と送って終了（保存しない）。
       manifest.prices.yahoo_incomplete に基準日より新しい日付があれば、原因として「Yahooが○○日の終値を未確定（空欄）のまま配信しているため。修正されしだい自動で取り込みます」と添える。
   - 同じ基準日の日次がすでに保存済み（state/latest_daily の as_of_market_et が一致）なら、1回目でも再試行でも何も送らず終了する。
4. リポジトリの活動（60日停止の予防）：
   - manifest.repo_last_commit_main から経過日数を出す。45日以上なら、レポート冒頭に
     「GitHubのリポジトリを更新してください（tickers.txt を開いて1行コメントを足して保存するだけで足ります）」と警告する。
   - manifest.keepalive が "failed" なら、その旨も添える。
5. 前回状態：保管ページDBの state/latest_daily、state/scenarios を読む。同じ基準日の日次が保存済みなら二重保存しない。

## 1.5 冒頭ブロック（レポートの先頭。第2節より前。05の0節の形）
- 「今日のひとこと」3〜4行：
  - 相場：レジームを05の1節の言葉で（記号を括弧に）。仮の判定ならその旨。例「高値圏で売りが増えている。大型株だけが崩れて指数を押し下げている（C、確定）」
  - 半導体・テクノロジー：テック内部のラベル（05の3節）と SOXX の位置を1行。例「IT銘柄の6割が高値から2割以上下げ、下げが表に出た（broad_decline）。SOXXは最高値から28%下」
  - やること：05の5節の言い方でレジームから決める。ゲート該当があればそれを先に。候補数、決算が近い銘柄の扱い、FB1_stalling の条件も1行に収める。
    例「新規は原則見送り（C）。候補なし。持ち株は崩れの合図（21EMAと50日線の同日割れ）を確認」
    ［v4.5］ヘッジ：signals.hedge.allowed が真なら同じ行に「ヘッジ：条件成立（SPY、H1、損切り774。置くかは判断）」または「ヘッジ：検討できる地合いだが今日は条件未成立」。偽なら書かない。
    ［v4.5］4行目に「長く持つ分の目安 ○%（buy／sell、○月○日から）」（signals.spy_model）。短期の「やること」と混ぜない。
- 「なぜその判断か」3〜5行：
  - signals.tape.reasons を言葉にしたものを最初に。続けて、判定を押し上げた要因と抑えた要因を分けて、チェックリストの値から1行ずつ（言葉 → 数字（記号））。
    例「押し下げ：大口が売った日が直近5週で7日（IX2＝7、危険水準）／指数が50日線を割った（SPY・QQQとも）／抜けても伸びないブレイクが続く（FB1_stalling、平均リターン−0.6%）」
    例「支え：上向きの銘柄は6割（BR1＝60%、4週前25%）／中小型のほうが強い（BR3＝+6%）」
  - 最後の1行は「判断が変わる条件」を数値で。例「SPY・QQQが終値で50日線を回復し、大口の売りが4日以下に減れば回復（E）に戻る／SPYが200日線を割れば底打ち試行（D）」
- Daily Plan の候補がある日は、やることの行に「候補n件（第6節）」と書く。

## 2. 日次で逃さない重要ポイント（必ず冒頭ブロックの直後に列挙）
signals.key_events_today をすべて書く。空なら「本日の重要イベントなし」と書く。種類ごとの扱い：
- regime_change：Tapeレジームの変更（hysteresisがprovisionalなら「確認待ち」と明記）。
- new_ready：新しいセットアップready（銘柄、型、P、S、リスク幅）。決算5営業日以内なら「見送り」。
- near_pivot：ピボットまで3%以内。Daily Planの候補。
- breakout：価格ブレイク。rvol50と出来高確認、weak（弱いブレイク）を併記。
- squat：ブレイク未達で押し戻し。「1〜2日、最長10日の回復待ち」と書く（E11.1）。
- pivot_failure / stop_touched：追跡中のブレイクの失敗・ストップ抵触。
- setup_failed：登録セットアップの崩れ。
- leader_weakness：先導株の50日線割れなど（弱さの中での売り検討）。
- climax_watch / climax_alert：強さの中での売り検討（該当項目を書く）。
- earnings_within_5d：決算5営業日以内（新規通常サイズは見送り、保有はイベント確認）。
- sector_rs_flip：セクター内区分がリーダー⇄ラガードに変わった（v4.3 E7.1。基準ETFを併記）。
- next_candidate_new / next_candidate_out：調整耐性の「次の候補」に新しく入った／外れた（v4.3 E7.2。tier A/B/C、下げ耐性・戻りの区分）。監視候補であり買いではない。
- late_break_new：「後崩れ」（下げに耐えたが戻りで売られている）に新しく入った。保有中なら弱さの中での売り検討の材料。
- rs_line_lead：RSライン（対SPY）が52週高値を更新したのに株価はまだ高値の下（RSが株価に先行。v4.3b E7.3）。市場が下げている日ほど注目。候補であり買いではない。
- rs_line_new_high：RSラインと株価がそろって52週高値（前回のRS新高値から20営業日以上あいたもの）。
- breadth_label_change（v4.4）：S&P500全体（sp500）またはテック内部（tech＝IT＋通信）の隠れ弱気ラベルが変わった。to_ja をそのまま書き、
  pct_down20（高値から−20%以上の銘柄比率）と基準ETF（SPY／XLK）の高値からの位置を添える。
- index_breakdown_guard（v4.4）：指数の崩れガード（SPYかQQQが50日線の下、かつ分配日5以上）が on／off になった。
  on なら「内部が改善していても回復（E）とは判定しない」、megacap_led が真なら「大型株主導の崩れ」と書く。
- breakout_stalling（v4.4）：ブレイクの「伸び」判定が変わった。on＝抜けた水準は守るが平均リターンがマイナス（ダマシが多い地合い）、
  off＝伸びが戻った。D+5維持率とD+5・D+10平均リターンを添える。
- leadership_shift（v4.5 E7.4）：kind=top_sectors は市場を引っ張る業種の上位3が前日から変わった（from→to と数）。
  kind=tech_halved は半導体・テクノロジーの先導株が4週前の半分以下に初めて減った（tech_now／tech_4w_ago、半導体の数）。「自分の領域が置いていかれ始めた合図」と添える。
- hedge_setup（v4.5 C10.1）：ヘッジを入れる条件が今日そろった。銘柄、水準（setup_level：H1／H2。D部の最終 hedge_level とは別）、きっかけ、終値、損切り（種類と距離%）、出来高比、解除条件を書く。
  「置くかどうかは判断。目的（方向性かベータ低下か）を決めてから」と添える。
- hedge_cover（v4.5）：ヘッジを外す条件がそろった（理由：FTD成立／レジームがA・B・E。損切り到達による解除は自分で管理）。
- spy_model_signal（v4.5 F10）：長期SPY配分モデルの buy／sell が変わった（合計点、5項目の内訳）。「長く持つ分の目安であり短期の判断とは別」と添える。
決算日は Yahoo の非公式データなので「要確認」と添える。

## 3. Tape（signals.tape）
- regime_effective、regime_checklist、hysteresis、provisional、reasons、previous_confirmed。
- チェックリスト表：SPY/QQQ（50日線・200日線・200日線の向き・52週高値比）、IX2（有効分配日）、
  BR1（50日線上比率と4週前）、BR2（新高値−新安値5日平均と4週前）、BR3（RSP/SPY 4週）、
  LD1（市場全体の先導候補数と4週前、セクター数）、FB1（ブレイク追随率 D+5 と4週前、件数）、
  index_state（分配日の日付、ストーリング、ラリーアテンプト、FTD）。
- ［v4.4］表に次の行を加える（04追補）：
  ・FB1は「D+5維持率／平均リターン D+5・D+10／伸び判定（FB1_extends・FB1_stalling）」の3つで書く。
    FB1_stalling なら「抜けた水準は守るが伸びていない（ダマシが多い地合い）。新規は抜けた後の続き（D+3〜5）を確認してから」と一言添える。
  ・IX3（指数の崩れガード、IX3_index_breakdown_guard）。成立なら理由（大型株主導の崩れ／指数の崩れ）。
  ・BR4（S&P500で高値から−20%以上の銘柄比率と4週前、ラベル）。ラベルが stealth なら「隠れ弱気」と明記。
  ・C_support_met（Cの支持件数）。
- ［v4.5］Tape表の下に「先導セクター」2行（signals.leadership。05の言葉で）：
  ・市場を引っ張る業種の上位3（今の数／4週前の数。例「ヘルスケア23（4週前7）、エネルギー12（7）、情報技術7（30）」）と、先導株の合計（今／4週前）。
  ・半導体・テクノロジーの先導株数（今／4週前。tech.halved_vs_4w が真なら「4週前の半分以下」と明記）。
- ［v4.5］「ヘッジ」1行（signals.hedge）：許可（allowed）、今日の成立（setups）、解除（cover_signal）。許可外なら「検討できる地合いではない」。
- ［v4.5］「長く持つ分の目安」1行（signals.spy_model）：配分%、buy／sell、いつから、5項目のうち×の項目。
- 市場内部とFB1は現在のS&P500構成銘柄からのproxy（生存者バイアス）と注記する。
- レジームの定義はマスター仕様C15.1（改訂版）と04追補のC15.1a〜d。判定はエンジンの値をそのまま使う。

## 4. Broad（短く）
- 日々動く項目だけ：S&P500・NASDAQ（signals.market）、SOX（signals.market に無いので SOXX＝signals.tech_etf で代用）、VIX、2年・10年金利、HY OAS、ドル円、原油、当日〜翌営業日のイベント。
  金利・HY・為替・原油・イベントはWeb検索で取得し、出典と基準日を付ける。
- Broad点は週次で確定。日次は「据置（前回週次：○点・○○）」を基本とし、判定帯をまたぐ明確な変化がある場合だけ暫定値と理由を書く。
- マクロ値は state に保存しない（表示のみ。保存は週次）。

## 5. 半導体・テクノロジー
- ［v4.4］最初に「テック内部」を1行（signals.breadth_ext）：tech の pct_down20 と4週前、pct_above_50sma、ラベル（label_ja）、
  XLKの高値からの位置、ex_tech との差（tech_minus_ex_tech_down20_pt）。
  stealth なら「XLKは高値圏だが構成銘柄の過半が高値から20%以上下げている（隠れ弱気）」、broad_decline なら「XLKも−10%超で下げが表面化」。
  megacap_led が真なら「市場全体の中身は改善しているが、大型・AI株主導で指数が崩れている。市場全体の改善を半導体・テクノロジーの追い風と読まない」と添える。
  ［v4.5］同じ行に、監視グループ別の先導株数（signals.leadership.tech.by_group：半導体／ソフトウェア／ハードウェア、今／4週前）を添える。
- tech_etf（SOXX、SMH、XLK、VGT、IGV、CIBR、SKYY、SOXL）：1日・1週・1か月のSPY比、50日線・200日線との位置。
- tech_leaders（市場全体のRS百分位80以上かつTT価格7項目クリア）：銘柄、区分、RS、SPY比63日、52週高値比。
- tech_watch：RS80以上だがTT未達、またはTT達成だがRS未達の銘柄（TT項目数、RS）。
- setups：ready → watch → forming の順。各行：銘柄、型、フットプリント、P、S、リスク幅、ピボットまでの距離、DRY5。
- ledger_cohorts：setup_type別のD+3/5/10（件数が20未満なら参考値）。
- sell_signals：先導株・母集団のクライマックス／弱さ。
- sector_rs（v4.3）：グループごとにリーダー上位3・ラガード下位3（rel_sec_63_pct）。セクター自体が指数に負けていれば「弱いセクターの中で相対的に強い」と書く。

  R_held・R_now は倍率なので dd_low・dd_now を併記する。リストは監視候補の順番であり、買いはピボット・ブレイクで判定する。
- rs_lines（v4.3b、RSライン＝銘柄÷SPY。RSIとは別物）：
  ・1行目：SPYの52週高値からの位置、監視母集団でRSラインが21日EMAの上にある数（summary.above_ema21_count）、
    S&P500∪監視母集団でRS新高値の件数（market.rs_new_high_count、市場情報として件数だけ）。
  ・RS新高値（summary.rs_new_high）とそのうち先行（summary.rs_leads_price）。なければ「なし」。21日EMAの上抜け・下抜け（crossed_up／crossed_down）。
  ・core（SOXX、SMH、XLK、IGV、NVDA、AVGO、AMD、TSM、MU、MSFT、ORCL）を短い表で：EMA21の上下、EMAとの差%、RSの52週高値からの位置%、株価の52週高値からの位置%、対QQQでEMA21の上下。
  ・一言添える：「RSラインは強い銘柄を拾う道具で、新高値でも下落しない保証ではない。買いはピボット・ブレイクで判定する」。SOXLはSOXXで代用。

## 6. Daily Plan（F4）
- 前提：regime_effective と適用ゲート → 新規許容度（なし／Pilot／通常）。
  F・D・Transition（provisional）は新規なし。Cは原則なし（例外はE12）。E・BはPilot〜選別。Aは通常。
- 候補：ready と near_pivot の銘柄。各行：P、E_plan（=1.001P、注文トリガー未設定時）、E_max（=min(1.05P, S/0.93)）、
  S、リスク幅、決算日（要確認）、許容サイズ区分、無効化条件。決算5営業日以内は見送り。
- ［v4.4］signals.tape.checklist.FB1_stalling が真なら、全候補に「ブレイク後D+3〜5の続き（水準維持と出来高）を確認してから」の条件を添える。
- ［v4.5］ヘッジ候補を1行（signals.hedge）：許可中で成立した日は、銘柄、水準（setup_level H1／H2＝D部の5〜15%／15〜30%）、損切り、解除条件（FTD成立またはレジームA・B・E。損切りは自分で管理）。置くかは判断。
  成立していない日は「ヘッジ：条件未成立（許可中）」。許可外なら書かない。数量は出さない。
- 米国時間（ET 9:30〜16:00。日本時間は夏時間22:30〜5:00、標準時間23:30〜6:00）とユーザー設定の注文手段を前提にする。
  今夜の米国取引開始までに使える形にする。
  設定が null なら価格水準と条件だけを示し、注文方法の可否は断定しない。
- 保有銘柄はユーザー提供時のみ扱う。
- 前回Daily Planの結果：発動・見送り・squat・失敗（判明分のみ）。

## 7. 出力と保存
- report_id：YYYYMMDD-DAILY（基準日）。
- SendUserMessage：冒頭ブロック（第1.5節と同じ文：今日のひとこと3〜4行＋なぜその判断か）、重要ポイント（第2節）、Tape（レジーム・変化）、
  先導セクター（上位3と半導体・テクノロジーの先導株数、4週前比）、テック内部（第5節冒頭：ラベルと高値から−20%以上の比率）、
  RSライン（新高値・先行した銘柄、EMA21の上にある数。なければ「なし」）、ヘッジ（許可・成立）、長く持つ分の目安（%とbuy／sell）、
  Daily Planの候補数、データ状態。すべて05の言葉で、記号は括弧。
- 本文の巻末に「読み方」：そのレポートで使った記号だけを05から1行ずつ転記。
